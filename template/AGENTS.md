# AGENTS.md

本文件是新项目的 AI 协作路由入口。

使用方式：

- 可以复用本模板中的通用路由规则、SDD 只读模式、阶段门禁、命令列表和回复要求。
- 必须由 AI 根据新项目事实填充“项目差异占位”。
- 不得照搬其他项目的技术栈专属红线，除非新项目代码、配置或文档能证明适用。

## 项目差异占位

AI 生成新项目根 `AGENTS.md` 前必须先只读分析：

- README / 项目文档。
- 构建文件和依赖声明。
- 配置文件和配置样例。
- 认证 / 鉴权入口。
- 数据访问方式。
- 外部依赖：缓存、消息、搜索、文件存储、第三方服务。
- 测试命令。

## 路由规则

普通问题：如果用户只是询问概念、解释代码、查询命令、查看文件、只读分析或讨论方案，且没有要求修改代码、修改业务行为、生成 SDD 产物或执行 SDD 命令，直接回答；不主动读取完整 SDD。

SDD 只读模式：如果用户问题涉及项目现有行为、模块职责、架构判断、业务规则、历史变更、为什么这样实现，或要求基于项目事实做判断，即使不修改代码，也应进入 SDD 只读模式，读取 `docs/sdd/AGENTS.md` 后按需读取相关 SDD 文档；不得修改代码或 SDD 产物。

意图模糊：如果无法明确判断用户是在普通问答、SDD 只读咨询还是要求开发变更，不要猜测；先用一个简短问题向用户确认目标和是否需要修改代码。

必须进入 SDD：以下任一情况不能直接改代码，必须按 SDD 流程处理：

- 用户输入 `sdd-*`。
- 用户要求修改、增加、删除代码。
- 用户要求修改业务行为、接口行为、数据口径、权限、安全、配置、数据存储语义、文件处理语义或其他生产行为。
- 用户要求生成或更新 `spec.md`、`plan.md`、`tasks.md`、`validate.md`。
- 用户要求执行实现、验证或归档。
- 变更涉及新项目定义的生产高风险区域。

## 代码修改硬门禁

- 没有当前 feature 时，先执行 `sdd-use`。
- 没有 Confirmed `spec.md`，不得编码。
- 没有 Reviewed `plan.md`，不得编码。
- 没有 Approved `tasks.md`，不得修改业务代码或测试代码。
- 用户即使要求“直接改代码”，也必须先走 SDD 阶段门禁。

进入 SDD 后读取：

- `docs/sdd/AGENTS.md`
- `docs/sdd/commands/AGENTS.md`
- 当前命令对应的 `docs/sdd/commands/{command}.md`

## SDD 命令

支持短命令：

```text
sdd-bootstrap
sdd-use {feature}
sdd-help
sdd-status
sdd-spec
sdd-plan
sdd-tasks
sdd-apply
sdd-validate
sdd-archive
```

如果使用 Codex，可按需复制 `.codex/skills/sdd-*`。如果不使用 Codex，只保留 `docs/sdd/commands/*` 作为工具无关规则源。

## 强制红线

通用红线：

- 不记录、输出或提交密码、Token、密钥、私钥、数据库凭证或生产请求凭据。
- 不绕过项目认证 / 授权上下文获取当前用户身份。
- 不新增依赖，除非说明必要性并经过 SDD 方案确认。
- 不修改未列入 `spec.md`、`plan.md`、`tasks.md` 的接口、字段、状态、配置、数据结构或公共行为。

## 回复要求

普通问答直接回答。

执行 SDD 命令或修改代码时，最终回复必须简洁包含：

- 修改的代码文件。
- 修改的 SDD 文件。
- 验证命令。
- 验证结果。
- 未执行验证及原因。
- 是否发现 SDD 与代码冲突。
